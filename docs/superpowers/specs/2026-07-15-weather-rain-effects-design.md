# Weather Pro 动态天气场景设计

## 背景与目标

Weather Pro 当前已经展示实时天气数据，但页面氛围不会随天气变化。本次改造新增覆盖全页面的动态天气场景，让用户在阅读数值前就能感知晴、多云、阴、雨、雪、雷暴、雾霾和沙尘。

已确认采用“克制氛围型”视觉语言：半透明自然元素融入现有浅色玻璃界面，天气特征明确，但正文与操作始终优先。

成功标准：

- 当前天气能稳定映射到一种主场景，未知状态安全回退。
- 晴天有太阳与辐射光芒，晴朗夜间改为月光。
- 云、雨、雪、雾带和沙尘的横向运动受风向与风速驱动。
- 阴天使用乌云；雨和雷暴组合乌云与降水；雪天展示小雪花。
- 动效不阻挡交互、不造成布局偏移，并控制移动端粒子数量。
- Mock 模式可复现每一种主场景，测试夹具覆盖夜间和混合降水变体。

## 数据来源与分类

天气分类优先读取和风实时天气的 `now.icon`，中文 `now.text` 只作为缺失或新增图标代码的兜底。和风官方说明图标代码可能更新，因此未知代码不能抛错或猜测。

分类映射：

- 晴：`100`；晴朗夜间：`150`。
- 少云/多云：`101`–`103`、`151`–`153`。
- 阴：`104`。
- 雷暴：`302`–`304`。
- 雨：`300`–`301`、`305`–`318`、`350`–`351`、`399`。
- 雪及雨雪混合：`400`–`410`、`456`–`457`、`499`。
- 雾：`500`–`501`、`509`–`510`、`514`–`515`。
- 霾：`502`、`511`–`513`。
- 扬沙/浮尘/沙尘暴：`503`–`504`、`507`–`508`。
- `900`、`901`、`999` 和其他未知代码：进入文本兜底；文本仍无法识别时使用默认背景。

文本兜底按优先级匹配：雷/冰雹 → 雨夹雪/雪 → 雨 → 沙尘/扬沙/浮尘 → 霾 → 雾 → 阴 → 多云/少云 → 晴。优先级避免“雷阵雨”被普通雨提前匹配。

Resolver 决策顺序固定如下：

1. 已知天气图标直接决定主类别，`text` 和 `precip` 不得覆盖。例如 `icon=101` 且 `precip=0.2` 仍是多云。
2. 图标缺失、`900`、`901`、`999` 或其他未知代码时才使用文本兜底。
3. `precip` 只调整已确定降水类别的强度，不能把晴或多云提升为雨。
4. 混合降水图标 `404`–`406`、`456` 输出 `kind=snow` 且 `precipitationType=mixed`；其他雪图标输出 `precipitationType=snow`，雨与雷暴输出 `precipitationType=rain`，其余为 `none`。
5. 夜间专用图标 `150`–`153`、`350`–`351`、`456`–`457` 输出 `isNight=true`。缺少可识别图标时固定按白天表现，不读取系统时钟，也不凭位置猜测日出日落。

仅在独立的 `weatherStatus === "success"` 且 `now` 有效时展示场景。分钟预报只表达未来降雨，不提前改变当前场景。

参考资料：

- [和风天气图标代码说明](https://dev.qweather.com/docs/resource/icons/)
- [和风实时天气字段](https://dev.qweather.com/en/docs/api/weather/weather-now/)

## 架构与组件

新增纯函数 `resolveWeatherScene(now, weatherStatus)`，把接口数据转换为稳定场景配置：

```text
{
  kind: clear | cloudy | overcast | rain | snow | thunder | fog | haze | dust | none,
  isNight,
  precipitationType: rain | snow | mixed | none,
  intensity,
  cloudCover,
  cloudLayers,
  windFactor,
  windDirectionX
}
```

新增顶层 `WeatherEffects`，固定覆盖视口，并按配置组合小型表现组件：

- `CelestialEffect`：太阳、月亮和光芒。
- `CloudLayer`：白云或乌云，可创建 1–3 个不同深度的云层。
- `RainLayer`：雨滴。
- `SnowLayer`：雪花。
- `LightningLayer`：低频闪电。
- `AtmosphereLayer`：雾、霾和沙尘。

各组件只接收归一化配置，不直接理解 API 字段。场景解析可独立测试，视觉组件可独立调整。

`App` 增加独立的 `weatherStatus` 与 `weatherError`，城市搜索错误继续独立保存。加载新城市时隐藏旧场景；失败时显示默认背景。天气请求使用递增请求标识并可配合 `AbortController`。请求标识检查必须保护 `try`、`catch`、`finally` 的所有天气、错误和状态写入；取消或过期请求不得修改任何状态，`AbortError` 不展示为天气错误。

## 风速与风向

优先解析 `wind360`，并归一化到 `[0, 360)`；缺失时将中文八方向映射为角度。无法识别、“无持续风向”、“旋转风”或“静风”按无横向风处理。

气象角度 `θ` 是风的来向：0° 为北风，90° 为东风。屏幕始终保持向下的正 Y 降落，只用东西分量驱动 X：

```text
windDirectionX = -sin(θ × π / 180)
windFactor = clamp(validWindSpeed / 50, 0, 1)
```

因此东风向左、西风向右，纯南北风不产生横移。无法解析、负数按 0 处理，极大值按上限截断。所有横向天气运动统一应用 `hasHorizontalWind = windSpeed >= 3 && abs(windDirectionX) >= 0.05`；否则横向位移为 0。

云量使用 `cloudFactor = clamp(validCloud / 100, 0, 1)`。字段缺失时默认值和层数为：多云 `101/151` 为 0.7、3 层；少云 `102/152` 为 0.35、1 层；晴间多云 `103/153` 为 0.5、2 层；阴 `104` 为 0.9、3 层；雨、雪、雷暴为 0.85、3 层；其他为 0、0 层。字段有效时按 `<0.4 / <0.65 / >=0.65` 映射为 1/2/3 层，但不改变已确定的主类别。

## 场景表现

### 晴与晴朗夜间

- 白天在视口右上方显示柔和太阳光球、12 条低透明度光芒与两层径向光晕。
- 光芒 18 秒缓慢旋转，光晕 4.8 秒轻微呼吸，不随风移动。
- `150` 使用月亮和冷色月晕，取消日光射线。

### 少云/多云

- 少云 1 层、多云 2–3 层半透明白云；白天保留减弱后的太阳，夜间保留月亮。
- 云量优先参考 `now.cloud`；缺失时使用上一节默认值。
- 有横向风时，云层沿 `windDirectionX` 移动；完整穿屏周期为 `cloudDuration = clamp(38 - windFactor × 28, 10, 38)` 秒。
- 无风时云层不横移，只保留非常轻的透明度呼吸。

### 阴

- 使用 2–3 层灰色乌云带和低透明度冷色遮罩，不展示太阳。
- 云层遵循相同风速规则；无风时保持静止。

### 雨

- 组合乌云层与雨滴层。仅由当前 `now.icon`/`now.text`/`now.precip` 判定，未来分钟降雨不提前触发。
- `precipFactor = clamp(validPrecip / 5, 0, 1)`；雨的 `intensity=max(0.15, precipFactor)`，雷暴为 `max(0.35, precipFactor)`。分类已经确定后，即使降水值为 0 也保留最低强度。
- 桌面雨滴数量为 `24 + round(intensity × 48)`，上限 72；移动端上限 40。
- 横向位移为 `windDirectionX × windFactor × 180px`，垂直位移始终超过视口高度。
- 基础周期为 `rainDuration = clamp(1.15 - intensity × 0.35 - windFactor × 0.25, 0.55, 1.2)` 秒，每滴乘以 0.85–1.15 的确定性系数后再次限幅；雨滴长度 18–34px，透明度 0.18–0.42。

### 雪及雨雪混合

- 使用小型圆点和简化六角雪花混合，缓慢下落并轻微摆动。
- 雪的 `intensity=max(iconMinimum, precipFactor)`；小雪/阵雪为 0.2，中雪为 0.4，大雪为 0.65，暴雪为 0.9，其他雪/混合降水为 0.35。
- 数量为 `18 + round(intensity × 38)`，桌面上限 56、移动端上限 32。
- 周期为 `snowDuration = clamp(5.5 - intensity × 1.4 - windFactor × 1.3, 2.8, 5.5)` 秒；有横向风时位移为 `windDirectionX × windFactor × 140px`，否则为 0，并叠加每片雪花的低幅摆动。
- 雨雪混合仍使用雪场景，但加入少量细雨线，雨线数量不超过纯雨场景的 25%。

### 雷暴

- 组合深色乌云、雨滴和低频闪电。
- 闪电用固定 8 秒 CSS 周期，在极短关键帧内完成两次弱闪，不使用随机定时器。
- 页面内容层不直接改变透明度，只让背景层短暂增亮，避免影响阅读和诱发强烈闪烁。

### 雾与霾

- 雾使用 3 层低透明度白灰雾带；霾使用偏灰褐色雾带与更低的背景对比度。
- 雾带不使用 CSS `filter: blur()` 处理正文，只在独立背景层绘制柔边渐变。
- 有横向风时周期为 `atmosphereDuration = clamp(60 - windFactor × 36, 24, 60)` 秒，并沿风向移动一个雾带宽度；否则保持静止。

### 沙尘

- 使用暖褐色薄雾与 `12 + round(windFactor × 20)` 个低透明度尘粒，桌面上限 32、移动端上限 18。
- 有横向风时，尘粒位移为 `windDirectionX × (160 + windFactor × 240)px`，周期为 `dustDuration = clamp(9 - windFactor × 6, 3, 9)` 秒；否则隐藏尘粒，只保留静态暖色薄雾。

## 视觉层级、性能与可访问性

- 场景层固定定位，覆盖视口，位于背景渐变之上、应用内容之下。
- 场景层统一设置 `pointer-events: none`、`aria-hidden="true"`，不参与焦点顺序。
- 只动画 `transform` 和 `opacity`，不改变布局尺寸，不新增第三方动画依赖。
- 所有粒子参数由索引经过确定性散列生成，相同输入不会因 React 重渲染跳动。
- 桌面端粒子上限：雨 72、雪 56、沙尘 32；移动端分别为 40、32、18；云层最多 3 个。
- `prefers-reduced-motion: reduce` 下保留静态太阳/月亮、云层和色调，隐藏雨、雪、尘粒与闪电，并禁用光芒旋转、云雾移动、透明度呼吸和场景过渡。

## Mock 场景

Mock 模式提供固定城市映射，复现每个主场景。字段顺序为 `icon / wind360 / windSpeed / precip / cloud`：

- 北京：晴，`100 / 0 / 0 / 0.0 / 10`。
- 海淀：有风多云，`101 / 90 / 18 / 0.0 / 72`。
- 杭州：阴，`104 / 180 / 12 / 0.0 / 95`。
- 上海：东风中雨，`306 / 90 / 28 / 2.4 / 94`。
- 深圳：东南风雷阵雨，`302 / 135 / 32 / 3.2 / 100`。
- 哈尔滨：西北风小雪，`400 / 315 / 16 / 1.2 / 88`。
- 重庆：微风雾，`501 / 0 / 4 / 0.0 / 100`。
- 石家庄：西风霾，`502 / 270 / 14 / 0.0 / 95`。
- 兰州：西风扬沙，`503 / 270 / 35 / 0.0 / 65`。

这些城市只用于 Mock 可复现体验；真实模式完全遵循接口返回值。测试夹具另外覆盖夜间晴 `150`、雨雪混合 `404`，以及 0/90/180/270 度四个风向，不需要继续增加演示城市。

## 错误与边界处理

- 加载、天气请求失败、`now` 缺失：隐藏具象场景并显示默认背景。
- 分钟接口失败但实时天气有效：仍按实时天气显示场景。
- `icon` 缺失、`900`、`901`、`999` 或未知：使用文本兜底；文本也未知时回退 `none`。
- 风速、角度、降水和云量为非法、负数或极大值：分别回退或限幅，绝不生成 `NaN` CSS 值。
- 快速切换城市：拒绝过期响应，加载期间不保留旧城市效果。

## 验证计划

1. 将纯解析逻辑放在 `src/weather-effects.js`，测试放在 `src/weather-effects.test.js`，使用 Node 内置 `node:test`，并新增 `npm test` 脚本执行 `node --test src/weather-effects.test.js`。
2. 自动化断言覆盖全部图标集合、已知图标高于文本和降水值、混合降水标志、文本优先级、夜间图标、未知值、非法数值、0/90/180/270 度风向、粒子数量、周期和位移上下限。
3. 运行 `npm run build`，确保 JSX 与 CSS 编译成功。
4. 在 Mock 模式依次搜索九个示例地点，确认主场景种类和组合元素正确。
5. 东风元素向左、西风向右、南北风无横移；风速越大周期越短且不突破上下限。
6. 当前无雨但分钟预报稍后有雨时，不提前显示雨雪层。
7. 通过延迟两个天气请求快速切换城市，确认旧请求的成功、失败和 `finally` 分支均不能覆盖新城市状态，`AbortError` 不显示错误。
8. 窄屏检查粒子数量上限、文字可读性、搜索与滚动交互。
9. 模拟 `prefers-reduced-motion: reduce`，确认仅保留静态场景且所有指定动画关闭。
10. 启动开发服务并检查 `/api/health`、页面加载和场景层 `pointer-events: none`。

## 非目标

- 不重做现有页面布局、业务卡片或配色体系。
- 不加入独立的用户动画设置面板。
- 不模拟真实流体、云体积或复杂粒子碰撞。
- 不使用未来预报驱动当前背景；页面只表现实时天气。

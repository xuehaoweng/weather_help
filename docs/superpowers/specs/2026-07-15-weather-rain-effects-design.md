# Weather Pro 动态雨幕设计

## 背景与目标

Weather Pro 当前已经展示实时天气、分钟级降水和风速，但页面背景不会随天气状态变化。本次改造为雨天增加覆盖全页面的氛围雨幕，让用户不读数值也能感知当前天气。

成功标准：

- 晴天或无降水时不显示雨幕。
- 下雨且风弱时，雨滴接近垂直落下。
- 下雨且有风时，雨滴根据风向倾斜，并随风速加快。
- 动效不阻挡操作、不降低主要文字可读性，并兼顾移动端性能和减少动态效果的系统设置。
- Mock 模式中可以稳定复现晴天与风雨天气，便于本地体验和回归验证。

## 已选方案

采用“全页面氛围雨”方案。雨幕位于应用内容与页面背景之间，覆盖整个视口。视觉上保持克制：雨滴透明、纤细，天气卡片和正文仍处于清晰的前景层。

未选择的方案：

- 仅在天气卡片内显示：性能最好，但天气氛围不够完整。
- 仅覆盖首屏：比全页面克制，但滚动后天气状态会突然消失。

## 组件设计

新增独立的 `WeatherEffects` 组件，由 `App` 传入当前天气、分钟级降水和加载状态。

组件职责：

1. 判断是否需要显示雨幕。
2. 将降水量、风速和风向转换为稳定的视觉参数。
3. 渲染固定数量、参数可复现的雨滴节点。
4. 通过 CSS 自定义属性把雨滴密度、长度、速度和横向位移传给动画。

`App` 继续负责请求与保存天气数据，不把动画规则混入数据加载逻辑。天气切换时，雨幕只做淡入淡出，不触发页面布局变化。

## 数据与视觉映射

### 降雨判定

满足任一条件时视为雨天：

- 当前天气文本包含“雨”或“雷阵雨”等降雨描述。
- 当前降水量大于 0。
- 分钟级预报中近期存在大于 0 的降水量。

加载中、请求失败或数据不完整时不显示雨幕，避免用错误状态制造天气效果。

### 降水强度

以当前降水和分钟级降水最大值作为强度输入，并限制到合理区间。强度主要影响：

- 雨滴数量：小雨较少，中到大雨逐步增加。
- 雨滴透明度与长度：强降水略亮、略长。
- 下落速度：强降水稍快，但不制造闪烁。

### 风向与风速

优先使用和风天气返回的 `wind360`；如果字段缺失，则把中文 `windDir` 映射为八个基本方向。气象风向表示风的来向，因此雨滴移动方向取其反方向。

风速映射为有限的横向位移与动画时长：无风时横向位移接近 0；风速增加时雨线更倾斜且周期更短。所有参数均设置上限，避免极端数据让雨滴近乎水平或动画过快。

## 视觉层级与交互

- 雨幕使用固定定位，覆盖视口，`pointer-events: none`，不拦截点击、滚动或表单输入。
- 应用内容放在更高层级；雨幕置于背景渐变之上、内容之下。
- 切换城市时使用短暂透明度过渡，避免雨幕突然闪现。
- 雨滴参数由索引生成，不在每次 React 渲染时调用随机数，避免抖动和不必要的 DOM 更新。
- 不新增动画库或其他运行时依赖。

## 可访问性与性能

- `prefers-reduced-motion: reduce` 下停止位移动画，仅保留非常淡的静态雨纹或完全隐藏雨滴。
- 雨幕标记为装饰性内容，不进入辅助技术的阅读顺序。
- 移动端减少雨滴数量与模糊效果；只动画 `transform` 和 `opacity`，避免触发布局计算。
- 雨幕不改变页面尺寸，因此不会造成布局偏移。

## Mock 数据与体验路径

保留北京为晴天示例，并让一个现有 Mock 城市返回带风降雨数据。用户运行 `npm run dev:mock` 后可通过城市搜索在晴天和风雨状态之间切换，无需真实 API Key 即可验证效果。

## 错误与边界处理

- 缺失风向时按无横向风处理，雨滴垂直落下。
- 风速或降水字段不可解析时回退到 0。
- 接口错误或加载状态下隐藏雨幕，现有错误卡片继续负责反馈。
- 未知天气文案不触发雨幕，除非数值降水数据明确大于 0。

## 验证计划

1. 运行生产构建，确保 JSX 与 CSS 编译成功。
2. Mock 晴天城市：确认无雨幕。
3. Mock 风雨城市：确认雨滴出现、方向倾斜、页面仍可操作。
4. 临时或自动化覆盖无风降雨输入：确认雨滴接近垂直。
5. 切换城市：确认雨幕平滑出现和消失，无布局跳动。
6. 检查窄屏布局和 `prefers-reduced-motion` 行为。
7. 启动开发服务并检查 API 健康状态和页面加载。

## 非目标

- 本次不加入雪、雾、雷电、云层等其他天气动画。
- 不重做现有页面布局、配色或组件体系。
- 不引入用户可配置的动画开关；系统的减少动态效果设置已经覆盖可访问性需求。

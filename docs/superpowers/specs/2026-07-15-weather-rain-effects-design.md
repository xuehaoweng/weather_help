# Weather Pro 动态雨幕设计

## 背景与目标

Weather Pro 当前已经展示实时天气、分钟级降水和风速，但页面背景不会随天气状态变化。本次改造为雨天增加覆盖全页面的氛围雨幕，让用户不读数值也能感知当前天气。

成功标准：

- 晴天或无降水时不显示雨幕。
- 当前正在下雨且风弱时，雨滴接近垂直落下；仅未来将下雨时不提前显示雨幕。
- 下雨且有风时，雨滴根据风向倾斜，并随风速加快。
- 动效不阻挡操作、不降低主要文字可读性，并兼顾移动端性能和减少动态效果的系统设置。
- Mock 模式中可以稳定复现晴天与风雨天气，便于本地体验和回归验证。

## 已选方案

采用“全页面氛围雨”方案。雨幕位于应用内容与页面背景之间，覆盖整个视口。视觉上保持克制：雨滴透明、纤细，天气卡片和正文仍处于清晰的前景层。

未选择的方案：

- 仅在天气卡片内显示：性能最好，但天气氛围不够完整。
- 仅覆盖首屏：比全页面克制，但滚动后天气状态会突然消失。

## 组件设计

新增独立的 `WeatherEffects` 组件，由 `App` 传入当前天气和独立的天气请求状态 `weatherStatus`（`loading | success | error`）。城市搜索错误与天气请求错误分开保存，搜索失败不会改变当前天气效果。

组件职责：

1. 根据当前天气判断是否需要显示雨幕。
2. 将降水量、风速和风向转换为稳定的视觉参数。
3. 渲染数量有上限、参数可复现的雨滴节点。
4. 通过 CSS 自定义属性把雨滴密度、长度、速度和横向位移传给动画。

`App` 继续负责请求与保存天气数据，不把动画规则混入数据加载逻辑。开始加载新城市时状态变为 `loading` 并隐藏旧雨幕；请求失败时状态变为 `error`，不会重新展示旧城市效果。每次天气请求使用递增请求标识或 `AbortController`，旧请求晚于新请求返回时不得覆盖当前城市。天气切换成功后，雨幕只做淡入淡出，不触发页面布局变化。

## 数据与视觉映射

### 降雨判定

仅在 `weatherStatus === "success"` 且 `now` 数据有效时判断当前是否正在下雨。满足任一条件时视为当前雨天：

- 当前天气文本包含“雨”等降雨描述。
- 当前降水量大于 0。

分钟级预报只表达未来降雨，不触发当前雨幕。加载中、请求失败、`now` 缺失或只有分钟数据时均不显示雨幕。后端 HTTP 200 但分钟接口部分失败时，只要 `now` 有效，仍可按实时数据渲染；实时天气接口失败则不渲染。

### 降水强度

以当前降水 `now.precip` 作为强度输入。先将不可解析、负数处理为 0，再使用 `intensity = clamp(precip / 5, 0, 1)` 归一化；天气文案明确为雨但数值为 0 时使用 `0.15` 的最小强度。未来两小时的最大降水不参与当前雨幕强度。强度映射如下：

- 桌面端雨滴数：`24 + round(intensity * 48)`，范围 24–72。
- 视口宽度不超过 640px 时雨滴数上限为 40。
- 雨滴透明度：`0.18 + intensity * 0.24`，范围 0.18–0.42。
- 雨滴长度：18–34px，由强度与每滴的确定性差异共同决定。
- 基础周期：`1.1 - intensity * 0.35 - windFactor * 0.2` 秒；每滴乘以 0.85–1.15 的确定性系数，最终限制在 0.55–1.2 秒。

雨滴参数由索引经过简单的确定性散列生成。组件只渲染当前需要的节点数，数量有明确上限；相同输入下节点位置和节奏保持一致。

### 风向与风速

优先使用和风天气返回的 `wind360`；将可解析数值归一化到 `[0, 360)`。如果字段缺失，则把中文 `windDir` 映射为八个基本方向。无法识别、“无持续风向”、“旋转风”或“静风”按无横向风处理。

气象角度 `θ` 表示风的来向：0° 为北风、90° 为东风。屏幕坐标始终保持向下的正 Y 位移，仅用风的东西分量控制 X：`directionX = -sin(θ)`。因此东风使雨滴向左、西风向右，纯南风或北风不产生横移，不会抵消下落。

风速先将不可解析、负数处理为 0，再使用 `windFactor = clamp(windSpeed / 50, 0, 1)`。雨滴在一次下落中的横向位移为 `directionX * windFactor * 180px`，限制在 -180px 到 180px；垂直位移始终大于视口高度。风速同时按上一节公式缩短周期，极端风速也不会突破位移和时长上限。

## 视觉层级与交互

- 雨幕使用固定定位，覆盖视口，`pointer-events: none`，不拦截点击、滚动或表单输入。
- 应用内容放在更高层级；雨幕置于背景渐变之上、内容之下。
- 切换城市时使用短暂透明度过渡，避免雨幕突然闪现。
- 雨滴参数由索引生成，不在每次 React 渲染时调用随机数，避免抖动和不必要的 DOM 更新。
- 不新增动画库或其他运行时依赖。

## 可访问性与性能

- `prefers-reduced-motion: reduce` 下完全隐藏雨滴，并禁用雨幕淡入淡出过渡。
- 雨幕标记为装饰性内容，不进入辅助技术的阅读顺序。
- 移动端减少雨滴数量与模糊效果；只动画 `transform` 和 `opacity`，避免触发布局计算。
- 雨幕不改变页面尺寸，因此不会造成布局偏移。

## Mock 数据与体验路径

保留北京 `101010100` 为晴天示例：`now.text = "晴"`、`now.precip = "0.0"`。上海 `101020100` 固定为风雨示例：`now.text = "中雨"`、`now.precip = "2.4"`、`now.wind360 = "90"`、`now.windDir = "东风"`、`now.windSpeed = "28"`，分钟数据可同步返回降雨但不参与当前效果判定。用户运行 `npm run dev:mock` 后搜索“北京”和“上海”即可稳定比较晴天与向左倾斜的风雨状态。

## 错误与边界处理

- 缺失或无法识别风向时按无横向风处理，雨滴垂直落下。
- 风速或降水字段不可解析、为负数时回退到 0，极大值按上限截断。
- 接口错误或加载状态下隐藏雨幕，现有错误卡片继续负责反馈。
- 未知天气文案不触发雨幕，除非数值降水数据明确大于 0。
- 快速切换城市时通过请求标识或取消机制拒绝过期响应；加载期间不会保留旧雨幕。

## 验证计划

1. 运行生产构建，确保 JSX 与 CSS 编译成功。
2. 搜索“北京”：雨滴容器不处于可见状态。
3. 搜索“上海”：雨滴出现，CSS 横向位移为负值，页面仍可点击、输入和滚动。
4. 当前无雨但分钟预报稍后有雨：雨滴容器不处于可见状态。
5. 无风降雨、北风或南风降雨：横向位移接近 0；东风为负、西风为正。
6. 缺失、非法、负数和极大风速/降水：参数分别回退到 0 或被限制在文档定义的上限内，不出现 `NaN` CSS 值。
7. 分钟接口失败但实时天气有效：按实时数据渲染；实时天气缺失或天气请求失败：雨幕隐藏。
8. 快速切换晴天与雨天城市：加载期间旧雨幕隐藏，完成后只显示最终城市对应状态，无布局跳动。
9. 视口宽度不超过 640px：雨滴节点不超过 40；桌面端不超过 72。
10. `prefers-reduced-motion: reduce`：雨滴不可见且雨幕无 transition。
11. 启动开发服务，检查 API 健康状态、页面加载以及雨幕层 `pointer-events: none`。

## 非目标

- 本次不加入雪、雾、雷电、云层等其他天气动画。
- 不重做现有页面布局、配色或组件体系。
- 不引入用户可配置的动画开关；系统的减少动态效果设置已经覆盖可访问性需求。

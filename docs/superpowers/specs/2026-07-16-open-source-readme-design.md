# Weather Pro 开源 README 设计

## 目标

把 Weather Pro 定位为可直接使用和部署的成品天气助手，而不是单纯的前端练习或项目模板。README 应让访客在几十秒内理解产品价值、看到产品界面，并能在三步内本地运行，从而提高试用、部署、Star 和贡献意愿。

## 受众与核心信息

主要受众是希望获得实用天气决策工具的中文用户，以及愿意自行部署的开发者。首屏核心信息是：Weather Pro 不只展示天气数据，还帮助用户在出门前判断穿什么、是否带伞，以及是否适合通勤或户外活动。

## 内容结构

1. 产品名称、中文价值主张、简短副标题、语言入口和项目状态徽章。
2. 真实产品截图或动图，让访客立即看到界面与信息密度。
3. 核心产品能力，突出分钟级降雨、预警、生活指数和通勤/户外/家庭建议。
4. 三步快速启动，默认使用 Mock 数据，不要求注册和风天气账号。
5. 真实天气数据配置和 Docker 部署入口。
6. 技术架构、项目结构、开发脚本及测试说明。
7. Roadmap、贡献方式、安全说明、License 和 Star 行动引导。

## 表达与视觉原则

- 中文 README 为主，顶部提供英文版入口。
- 先展示用户收益，再解释技术实现。
- 使用具体、可验证的能力描述，不虚构在线 Demo、用户量、性能数据或背书。
- 徽章只展示仓库可验证的信息，避免装饰性徽章堆叠。
- 截图必须来自当前项目实际界面；若本轮无法稳定生成截图，则保留清晰的截图资产计划，不使用虚假占位图。
- 快速启动命令保持可复制，明确 Node.js 前置条件、访问地址与 Mock 模式行为。

## 验收标准

- 访客在首屏能理解产品面向“出门决策”，而非普通天气数据展示。
- 新用户可按 README 在三步内以 Mock 数据运行项目。
- README 覆盖真实数据配置、Docker、测试、架构、贡献和安全入口。
- 所有命令、文件路径、端口和功能描述与当前代码一致。
- Markdown 链接有效，项目测试和构建通过。

## 范围

本轮修改中文 README，并在必要时同步英文 README 的入口或关键信息。不会虚构在线演示、发布版本或社区数据，也不新增与 README 无关的产品功能。

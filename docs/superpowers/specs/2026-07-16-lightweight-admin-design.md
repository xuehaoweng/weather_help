# Weather Pro 轻量管理后台设计

## 目标

为自托管 Weather Pro 提供一个无需用户账号、无需外部统计平台的轻量运营后台。管理员可以了解产品是否有人使用、哪些能力有价值以及服务是否健康，同时尽量减少个人数据收集。

本子系统在决策体验 MVP 完成后实施。

## 成功标准

- `/admin` 只有配置管理员密码后才能访问数据。
- 后台展示最近 7 天和 30 天的访问、场景、提醒与错误趋势。
- 统计仅保存每日聚合数据和短期匿名访客集合。
- 不保存 IP、User-Agent、精确经纬度、城市搜索原文或通知内容。
- 未配置管理员密码时，管理接口默认关闭。
- 统计写入失败不得影响天气查询和用户交互。

## 收集事件

服务端只接受白名单事件：

- `page_view`
- `city_selected`
- `scene_changed`，属性只允许 `commute`、`outdoor`、`family`
- `reminder_enabled`
- `reminder_disabled`
- `notification_sent`
- `client_error`，属性只允许预定义错误类别

客户端生成随机安装标识并保存在本机。发送统计时，服务端使用每日盐对标识进行哈希，只在对应日期的集合中用于估算日活。原始标识不写入磁盘，日活集合随每日聚合记录在 30 天后整体删除。

城市相关事件只记录“选择了一次城市”，不记录城市名称、搜索词或坐标。

## 数据存储

不新增数据库依赖。新增 `server/analytics-store.js`，将数据保存到 `.cache/analytics.json`：

```js
{
  version: 1,
  days: {
    "2026-07-16": {
      pageViews: 120,
      visitorHashes: ["..."],
      citySelections: 34,
      scenes: { commute: 20, outdoor: 8, family: 6 },
      reminders: { enabled: 7, disabled: 1, sent: 4 },
      errors: { weather_core: 2, weather_details: 5, notification: 1 }
    }
  }
}
```

写入采用单进程队列、临时文件和原子重命名。启动时校验版本与字段；文件损坏时隔离旧文件并从空聚合开始。只保留最近 30 个自然日。

该方案面向单实例自托管。多实例部署不在本阶段支持，后台中明确显示这一限制。

## API

- `POST /api/analytics/events`：接受单个白名单事件，限制请求体大小和属性字段。
- `POST /api/admin/login`：验证管理员密码，成功后设置短期 HttpOnly Cookie。
- `POST /api/admin/logout`：注销当前管理会话。
- `GET /api/admin/overview?range=7|30`：返回聚合指标和趋势。
- `GET /api/admin/health`：返回应用模式、上游错误计数、缓存状态和进程启动时间。

事件接口按来源地址进行轻量内存限流，但不持久化地址。超限返回 `429`。统计接口不可返回访客哈希集合。

## 管理员认证

- 密码从 `ADMIN_PASSWORD` 环境变量读取，不提供默认值。
- 未配置密码时，登录和数据接口返回 `404`，避免暴露未启用后台。
- 使用 Node.js `crypto.scrypt` 比较密码派生值，避免直接字符串比较。
- 登录成功后创建随机会话 ID，只保存在服务端内存中。
- Cookie 使用 `HttpOnly`、`SameSite=Strict`；生产环境启用 `Secure`。
- 会话闲置 30 分钟或服务重启后失效。
- 登录接口限制失败次数，避免暴力尝试。

## 后台界面

`/admin` 使用独立的 React 组件，但复用现有颜色、圆角、卡片和字体规范。页面包含：

1. 登录表单。
2. 7 天与 30 天切换。
3. 访问量、匿名日活、城市选择、提醒开启和通知发送指标卡。
4. 每日趋势表或轻量 CSS 图表。
5. 场景使用占比。
6. API 错误、运行模式、缓存状态和启动时间。
7. 隐私说明与单实例限制。

不引入重量级图表库。没有数据时展示明确空状态，不制造示例数据。

## 隐私与安全

- 页面首次加载不发送统计，只有应用成功渲染后发送 `page_view`。
- README 和后台说明收集字段、保留期限和关闭方式。
- 提供 `ANALYTICS_ENABLED=false` 完全关闭事件接收和客户端上报。
- API 对事件名和属性执行严格白名单校验。
- 管理接口使用同源请求和严格 Cookie，不允许跨域读取。
- 管理页面不得显示或导出访客级数据。

## 错误处理

- 统计存储不可写：记录服务端警告并丢弃事件，用户 API 继续正常工作。
- 聚合文件损坏：隔离文件并恢复空存储，后台显示存储恢复提示。
- 会话失效：后台返回登录页，不保留管理员密码。
- 管理 API 失败：页面展示可重试错误，不影响公开天气页面。

## 测试

- 事件白名单、属性过滤、请求体限制和限流测试。
- 每日聚合、匿名日活去重、30 天清理和原子持久化测试。
- 未配置密码、登录成功、登录失败、会话过期、注销和 Cookie 属性测试。
- 后台 overview 不泄露访客哈希测试。
- 统计存储失败不影响天气 API 测试。
- 管理页面登录、空状态、7/30 天切换和服务健康展示的浏览器验证。

## 非目标

- 普通用户账号、角色权限和用户封禁。
- 访客明细、行为回放、广告归因和跨站跟踪。
- 多实例共享统计和高可用数据库。
- CSV 导出、自动报表和第三方告警集成。
